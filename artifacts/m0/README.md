# M0 evidence

This directory is generated by `python m0_harness.py --out artifacts/m0`.

The three `local_probe` entries were collected by invoking `--version` and
`--help` only. They prove that these local executables expose the listed command
surfaces on this machine; they do not prove authentication, billing
compatibility, provider participation, session resumption, or idle wake.

The room lifecycle evidence is simulated and local. `idle_wake` is deliberately
false in `pass-fail.json`; queued delivery is the only safe behavior until a
real supported runtime test proves otherwise.

The event store persists idempotency keys, and the pass/fail record includes a
retry check proving that a repeated assignment does not create a second event.

Agent fixture posts use a fixed participant identity guard; the pass/fail record
also proves an unknown author is rejected. Real connector authentication remains
unverified.

The localhost integration proof is covered by `test_room_http.py`; it verifies
two clients, retry deduplication, acknowledgements, reconnect persistence, and
loopback-only binding.

`room_mcp.py` is the first disposable MCP-shaped connector. `room-mcp-capabilities.json`
and `test_room_mcp.py` show two stdio processes sharing the same room and fixed
participant identities. It has not been registered with Claude, Codex, or
Antigravity.

The connector refreshes the durable store before sync/post/wait calls; the
two-process test catches stale-reader behavior between separate connector
processes.

The connector can now use the SQLite/WAL backend with `--store sqlite`; the
enrollment plan uses that backend. JSON remains available only for fixture
compatibility.

`mcp-enrollment-plan.json` contains provider-specific add/remove commands from
the local help syntax. It is a dry run; executing those commands would change
provider configuration and now records the explicitly approved registration.

`mcp_preflight.py` runs a clean SQLite-backed handshake and validates those
command templates without invoking any provider configuration command. Its
result is written to `mcp-preflight.json`.

`live-mcp/live-mcp-results.json` records the first registered-provider attempt:
Codex and Antigravity discovered `room-m0` but their approval policies denied
`room_post`, and the authoritative SQLite room remained empty.

`provider-approval-findings.json` keeps those provider-specific denial causes
separate from transport and Room implementation evidence. No permission policy
was changed.

`room-wait-evidence.json` records the narrower wake result: an active connector
wait receives a new durable event, while provider idle wake remains unverified.

`build_m0_report.py` combines the local help probes, authorized live CLI
results, MCP preflight, and platform findings into `capability-matrix-live.json`.

`codex-protocol-probe.json` and `codex-schema/` are a local protocol-surface
probe produced by `codex app-server generate-json-schema`. This generated no
model turn and does not establish authentication, billing, or wake behavior.

`platform-findings.json` records that WSL is not installed on this host, so the
planned Windows-to-WSL managed-runtime path remains untested.

`interface-probes/` preserves the exact local version and help output used for
the capability matrix. These files contain command documentation only.

`mcp-enrollment-findings.json` records the local MCP subcommands. No MCP
configuration was added, removed, enabled, disabled, or authenticated.

`live-smoke-test-plan.json` and `live-smoke-test-runbook.md` describe the
bounded live test. The authorized run is recorded separately under
`live-smoke/`.

The authorized run is now under `live-smoke/`. Its summary distinguishes
Claude's weekly limit from successful Codex and Antigravity acknowledgements;
the bridge receipts are explicitly marked as captured-output ingestion rather
than native Room connectivity.
